## Расшифровка варианта

- **ИБ** - бесконечный источник заявок.
- **ИЗ2** - равномерный закон генерации заявок.
- **ПЗ1** - экспоненциальный закон времени обслуживания.
- **Д1ОЗ1** - постановка заявки в буфер по кольцу с использованием указателя.
- **Д1ОО3** - удаление самой старой заявки при переполнении буфера.
- **Д2П2** - выбор свободного прибора по кольцу с использованием указателя.
- **Д2Б2** - выбор заявки из буфера по принципу LIFO.
- **ОР1** - вывод двух итоговых сводных таблиц в автоматическом режиме.
- **ОД1** - пошаговое отображение состояния системы и календаря событий.

## Кратко о проекте

Проект моделирует работу сервисного центра по ремонту бытовой техники с использованием дискретно-событийного моделирования.

Заявки поступают от клиентов через случайные интервалы времени по равномерному распределению. Продолжительность обслуживания определяется по экспоненциальному распределению.

Если есть свободный мастер, заявка сразу передаётся ему на обслуживание. Если все мастера заняты, заявка помещается в общий буфер.

Постановка заявок в буфер и выбор свободного мастера выполняются по кольцу с использованием двух независимых указателей.

При переполнении буфера удаляется самая старая заявка, а новая занимает её место. Удалённая заявка учитывается как отказ.

После завершения обслуживания диспетчер выбора проверяет буфер. Если в нём есть заявки, выбирается последняя поступившая по принципу LIFO.

В текущей реализации используется один источник заявок. Количество мастеров и размер буфера задаются пользователем.

## Событийная модель

Моделирование основано на обработке двух типов событий:

- `REQUEST_GENERATED` - поступление новой заявки;
- `SERVICE_COMPLETED` - завершение обслуживания заявки.

Класс `Simulation` управляет процессом моделирования, а `EventCalendar` хранит будущие события в порядке модельного времени.

После достижения заданного количества сгенерированных заявок новые поступления не планируются. Моделирование продолжается до завершения обслуживания оставшихся заявок и опустошения календаря событий.

## Режимы моделирования

### Пошаговый режим (ОД1)

Перед началом моделирования отображается начальное состояние системы.

После каждого обработанного события выводятся:

- номер шага;
- текущее модельное время;
- обработанное событие;
- действия диспетчеров;
- состояние источника;
- состояние ячеек буфера;
- состояние мастеров;
- указатель постановки заявок в буфер;
- указатель выбора мастера;
- количество созданных, обслуженных и отклонённых заявок;
- текущая вероятность отказа;
- календарь будущих событий в виде таблицы.

Для перехода к следующему шагу необходимо нажать Enter.

Для досрочной остановки моделирования используется команда `q`.

После полного завершения моделирования выводятся итоговые таблицы.

| Параметр | Значение |

В данном сценарии на шагах 1 и 2 демонстрируется кольцевой выбор мастеров, на шагах 5 и 6 - кольцевая постановка в буфер, на шаге 7 - вытеснение самой старой заявки, на шаге 8 - выбор заявки по LIFO.

### Автоматический режим (ОР1)

В автоматическом режиме события обрабатываются без участия пользователя.

Количество заявок подбирается автоматически на основе результатов пробного моделирования.

Параметры статистического расчёта:

- относительная точность - 10%;
- доверительная вероятность - 0.9;
- начальное количество заявок по умолчанию - 100.

Необходимое количество заявок рассчитывается по формуле:

$$
N = \left\lceil
\frac{t_{\alpha}^{2}(1-p)}
{p\delta^{2}}
\right\rceil
$$

где:

- p - оценка вероятности отказа;
- t = 1.643 - коэффициент для заданной доверительной вероятности;
- delta = 0.1 - относительная точность.

Моделирование повторяется до выполнения критерия остановки:

- относительное изменение вероятности отказа между последовательными прогонами не превышает 10%;
- текущее количество заявок не меньше рассчитанного необходимого количества.

Если в результате прогона отказов нет, количество заявок увеличивается.

Для предотвращения бесконечного моделирования установлен предел в 200 000 заявок при обычном запуске. При достижении предела без выполнения критерия остановки выводится соответствующее предупреждение.

## Результаты моделирования

По окончании моделирования формируются две итоговые таблицы.

### Таблица 1. Характеристики источников

| Обозначение | Показатель |
|---|---|
| N | Количество сгенерированных заявок |
| Pотк | Вероятность отказа |
| Tпреб | Среднее время пребывания в системе |
| TБП | Среднее время ожидания |
| Tобсл | Среднее время обслуживания |
| DБП | Дисперсия времени ожидания |
| Dобсл | Дисперсия времени обслуживания |

Временные характеристики рассчитываются по обслуженным заявкам.

Вероятность отказа определяется как отношение количества отклонённых заявок к общему количеству сгенерированных заявок.

### Таблица 2. Характеристики приборов

Для каждого мастера выводятся:

- номер мастера;
- количество обслуженных заявок;
- суммарное время обслуживания;
- коэффициент использования.

Коэффициент использования определяется как отношение суммарного времени занятости мастера к общему времени моделирования.

## Проверка работоспособности

В ходе тестирования проверены:

- генерация и обслуживание заявок;
- кольцевая постановка заявок в буфер;
- кольцевой выбор свободного мастера;
- вытеснение самой старой заявки;
- выбор заявок по LIFO;
- совпадение результатов пошагового и автоматического режимов при одинаковом количестве заявок, параметрах и seed;
- изменение результатов при изменении количества мастеров, размера буфера и среднего времени обслуживания;
- моделирование с одной заявкой;
- отсутствие отказов при автоматическом подборе количества заявок;
- остановка при достижении установленного предела количества заявок.
